先找到路，再学会开车

你已经会用电脑，只是刚搬进一座路牌不同的城市。先把熟悉的 Windows 经验带进来：你会找到桌面、文件、软件和自己的工作区，然后才去碰系统设置。

这本书怎样陪你走

主线环境是 Ubuntu 24.04 LTS 桌面版，运行在 VMware Workstation Pro 17 的虚拟机里。你在 Windows 上启动 VMware，Ubuntu 则是里面那台独立的电脑。宿主机指外面的 Windows；来宾机指里面的 Ubuntu。两边的文件、账号、剪贴板和管理员权限都不是天然共用的。

五个理念差异：你不是从零开始

你熟悉的 WindowsUbuntu 里的对应物真正不同的地方
C:、D:、E: 把位置分成几棵树从 / 开始的一棵目录树硬盘分区和移动存储接到树上的某个目录，路径描述位置，设备本身另有名字。
从网页下载 .exe 安装包软件仓库与包管理器系统能一起记录依赖、来源和更新；也存在独立安装包，但不能把任意下载文件都当成可信软件。
资源管理器与命令提示符是两种入口Files 文件管理器与终端它们看的是同一批文件。终端让你把动作写清楚、保存下来、重复执行。
管理员确认框让一次操作提权普通账号与 sudo日常保持普通权限；只有需要管理系统时，才明确请求执行某条管理员命令。
通常看扩展名识别文件类型名字、内容、权限共同决定行为Linux 常用文件系统区分大小写；Main.cpp 与 main.cpp 可以是不同文件。没有 .exe 也可能是程序，有 .sh 也不代表能直接执行。
sudo · 词源、争议与助记
公认词源 / 官方释义争议说法 / 边界助记口诀（不是词源）
sudo 官方手册描述为以另一用户的身份执行命令；常被解释为 superuser do，默认目标通常是 root。它并不只支持超级用户，不能把“永远以 root 执行”当成完整含义。“这一次借管理员钥匙”。这是助记，不是权限免检通行证。

先认识 root：它既是“根”的英文，也是 Linux 超级用户的账号名。第 2 章会区分根目录 /、root 账号与它的家目录 /root。它们有关联，却是三件事。

终端快捷键：先学会停下来

在 Windows 的许多文字窗口里，你用 Ctrl+C 复制。终端沿用了更早的交互习惯：Ctrl+C 通常向前台程序发送中断信号。GNOME Terminal 把复制、粘贴放到 Ctrl+Shift+C/V，给“停止当前工作”留出原来的位置。

按键你可以这样理解边界
Ctrl+Alt+T打开一个 Ubuntu 终端窗口Ubuntu 默认桌面快捷键；可在设置中修改。先确保键盘焦点在来宾机。
Ctrl+Shift+C复制你选中的终端文字先选中文字；复制不会运行它。
Ctrl+Shift+V把剪贴板内容粘贴到终端粘贴多行命令可能立即开始执行；先在文本编辑器看清内容。
Ctrl+C请求停止当前前台程序，或取消当前输入程序可以处理或忽视这个信号；它不是撤销已经完成的文件操作。
Ctrl+L整理屏幕，让提示符回到上方不会删除文件，也不等于清除命令历史。
Ctrl+R向后搜索你执行过的命令看清匹配项，再按 Enter；按 Ctrl+C 放弃。
Ctrl+D在空输入行表示输入结束；交互 shell 通常退出它不是关机快捷键；不要拿它当复制键。

本章自检

复制终端文字应该按哪组键？Ctrl+C 又做什么？

在 GNOME Terminal 中先选中文字，再按 Ctrl+Shift+C。Ctrl+C 通常发送中断给前台程序，并不会撤销已完成的操作。

看到命令前的 $，需要一起输入吗？

不需要。它是提示符；页面的复制按钮会自动去掉行首的 $ 与其后的空格。

为什么 Ubuntu 虚拟机里的文件不会自动出现在 Windows 桌面？

宿主机和来宾机有各自的文件系统。你需要共享文件夹、经过配置的拖放，或网络传输来建立通道。

第一次练习应该选 /etc 还是自己的家目录？

选自己的家目录。/etc 保存系统配置，读懂之前不要改写。

避坑清单

  • 不要把 Windows PowerShell 命令粘进 Ubuntu 终端。
  • 不要靠复制整页来运行命令；一次看清一张命令卡。
  • 不要把“执行成功没有输出”误认为终端失灵。

Files 与输入法：先学三个小动作

Windows 的资源管理器地址栏可以输入路径；Files 也能做到。按 Ctrl+L 输入 ~/ 回家，或者输入 / 查看整棵目录树。Files 中的 Ctrl+L 是定位栏，终端中的 Ctrl+L 是整理屏幕：快捷键的意思由当前应用决定。

  1. 打开 Files → Home，看看桌面、文档和下载。中文系统可能显示本地化名称；本书示例用的 ~/Downloads 是一个明确的英文目录名，不保证就是你当前系统的“下载”目录。
  2. 按 Ctrl+H 显示以点开头的隐藏文件，再按一次收起。它们只是默认隐藏，并非都不能碰；不理解的配置文件先备份再改。
  3. 需要输入中文时，在“设置 → 键盘 → 输入源”添加合适的中文输入源，例如中文智能拼音。不同语言安装状态可能需要先补齐语言支持。用 Super+Space 切换输入源；已有快捷键配置时以设置面板为准。
IBus · 词源、争议与助记
公认词源 / 官方释义争议说法 / 边界助记口诀（不是词源）
Intelligent Input Bus，GNOME 常用的输入法框架。输入法框架与某个中文输入引擎不是同一个东西；系统可安装其他框架。“让键盘输入送到合适语言引擎的公交站”。这是助记。

在 Files 的文件夹空白处右键，Ubuntu 常见安装会出现“在终端中打开”。这样开的终端通常从当前文件夹起步。如果菜单里没有这项，先用 Ctrl+Alt+T 打开终端，再在第 3 章学习用路径走到目标位置。不要为找菜单去随意下载扩展。

宿主机与来宾机之间开一扇门

公认词源 / 官方释义争议说法 / 边界助记口诀（不是词源）

Wayland · 词源、争议与助记
公认词源 / 官方释义争议说法 / 边界助记口诀（不是词源）
显示协议与相关实现项目的名称，不是需要逐字母展开的缩写。它与 Xorg 的会话机制不同；某些 VMware 桌面集成行为在两者下不同。“桌面窗口和屏幕之间的一套交通规则”。这是用途助记。
剪贴板或拖放仍不通时

目录树：把陌生缩写变成地址

Windows 常从“我的文件在 C 盘还是 D 盘”开始找。Ubuntu 先问“它在根目录这棵树的哪根枝条上”。你不需要背一张神秘名单，只要记住每个地方负责什么。

为什么没有 C 盘：地址与硬件分开了

在 Windows 中，盘符常把卷放在不同入口；Windows 也支持挂载到文件夹，所以“所有 Windows 存储只能有盘符”并不准确。Linux 的日常路径则统一从 / 开始。一块分区可以挂载到根目录，另一块可以挂载到 /home，移动存储又可以挂载到 /media/你的用户名/卷标。你看到一棵树，下面可以连接多种存储。

FHS · 词源、争议与助记
公认词源 / 官方释义争议说法 / 边界助记口诀（不是词源）
Filesystem Hierarchy Standard，文件系统层次标准。它规定目录职责，不能保证每个发行版都采用一模一样的实现；现代 Ubuntu 的 /usr 合并布局就是需要一起理解的实例。“每条街有自己的用途”。这是助记。

挂载就像把另一盆树的枝条接到现有树上。设备名告诉系统“从哪里读”；挂载点告诉你“从哪条路径进去”。设备路径可能是 /dev/sdb1，但它并不保证永远是某一只 U 盘。第 9 章旁边的挂载沙盘会演示这种连接。

公认词源 / 官方释义争议说法 / 边界助记口诀（不是词源）

“一切皆文件”是一种接口观念

它不是说屏幕、进程和网卡都是普通文本。Linux 用文件描述符及文件操作接口统一了很多访问方式：普通文件、设备节点、管道都可参与其中。/proc 与 /sys 里的许多条目由内核运行时提供，读写它们可能是在查询或控制系统，而不是修改硬盘上一份文档。

本章自检


touch 一个已经有内容的文件，会不会清空它？

不会。touch 通常更新时间戳；创建新空文件只是目标不存在时的行为。




为什么 cp -r src backup 重复执行后，目录结构可能变化？

第一次 backup 不存在，创建副本；它已经是目录时，src 会被复制进该目录。先确认目标状态。




rm 删除的文件会去 Files 回收站吗？

通常不会。需要回收站缓冲时使用 Files 的“移到回收站”，或先移动到自己创建的待审目录。




tail -f 不返回提示符，是不是终端卡死？

不是，它在等待新日志。按 Ctrl+C 停止当前跟踪即可。

权限与身份：谁能开哪一扇门


Windows 的“以管理员身份运行”和文件属性里的“安全”页，在这里对应 sudo 与文件权限。你平时是房间的使用者，需要修公共设施时才临时借管理员的钥匙。






用户、用户组、root 与 sudo


文件有所有者，也有所属用户组。系统判断你对它能做什么时，会结合当前身份、组成员关系与权限。root 是管理员账户，通常拥有很高的系统权限；/root 是这个账户的家目录；/ 才是整棵目录树的根。这三个名字不要混在一起。


sudo / root · 词源、争议与助记






公认词源 / 官方释义争议说法 / 边界助记口诀（不是词源）

成因你会遇到什么先检查什么





1. 文件自身的 r、w、x 不够脚本可读却不能直接运行；文件能看却不能保存。看目标的权限，确认当前身份实际匹配哪组。



2. 路径中某层目录缺 x文件看起来可读，却连路径都走不到。检查每层父目录的搜索权限；不要只看最后一个文件。



3. 父目录缺 w 或 x无法新建、重命名或删除目录中的文件。改目录项需要父目录权限；文件自己的 w 不等于可删除。



4. 身份或组关系不符合预期项目被误用 sudo 创建；新加的组在旧会话未生效。核对所有者与当前 id 输出；组变更后常需重新登录。



5. 文件系统以 noexec 挂载明明有 x，直接执行仍被拒绝，常见于某些共享或移动介质。检查挂载选项；把自己可信的项目放到家目录开发。



6. ACL 或 AppArmor 等额外限制三组位看似允许，但仍然拒绝操作。查看访问控制规则与相关日志；不要盲目关闭安全机制。

本章自检


-rwxr-xr-- 是 755 吗？

不是，是 754。Others 当前只有 r；增加 x 后才是 755。




为什么文件可写，你仍可能无法删除它？

本机 C/C++源码与 build 分开，构建时使用普通用户。编译警告、调试器、测试和依赖管理。



嵌入式交叉编译项目在 ~/workspace，解压的工具链放 ~/tools。确认目标架构、交叉编译器、目标系统库；宿主机能运行不代表板子能运行。

本章自检


src、include、build 各存放什么？

src 放实现源文件；include 放头文件接口；build 放生成的构建配置与编译产物。




文件已经存在，为什么还会出现 No such file？

编译器只在规定的搜索路径中找头文件；文件存在不等于搜索路径已配置。




target_include_directories 修复了哪一层？

修复目标的编译包含路径；没有修改文件权限，也没有搬动文件。




为什么只在 apt 安装时用 sudo？

安装写系统目录；构建只需要写自己的工程。给整个构建加 sudo 容易产生由 root 拥有的产物。




避坑清单


  • 每块代码按顺序在同一个终端执行；先确认 pwd 位于新练习目录。
  • CMakeLists.txt 大小写必须正确。
  • 不要为“找不到头文件”直接改成全员可写权限。
  • 真实工程修改构建配置前先保存版本记录。

急救箱与速查：先判断，再动手


Windows 出问题时，你也会先看任务管理器、磁盘空间和文件位置。终端里的错误同样是一条线索，不是一张判决书。先读症状，再执行对应步骤；这里的复制按钮帮助你准确输入，不会替你判断现场。






01 · apt 被锁：有人正在使用同一本账


症状：Could not get lock 或 Waiting for cache lock。常见原因：软件更新器、自动更新或另一个 apt 正在工作。先关闭自己重复打开的安装任务，给正在更新的任务时间。


【Ubuntu 终端】



可复制命令



$ ps aux | grep -E '[a]pt|[d]pkg|[u]nattended'





像拆句子一样拆开这条命令



提示符
$ 是普通用户提示符，不输入；复制时自动移除。




命令本体
ps 输出进程快照；grep 过滤这些行；未加引号的 | 连接两者。




短选项
aux 是不带横线的 BSD 风格选项：a 扩大用户范围，x 包含无控制终端进程，u 使用用户友好的格式；grep -E 使用扩展正则表达式。




长选项
无




路径 / 参数
无文件路径；引号内的 | 表示匹配三种模式之一，不是 shell 管道；[a] 等写法避免 grep 常见的自匹配。








系统内部发生了什么：只查看可能占用包管理器的进程，不终止它们。看到进程并不自动意味着卡死，需要观察它是否仍在下载、安装或更新日志。


预期输出 · 示意输出

可能显示 apt、dpkg 或自动更新进程；没有匹配时通常没有输出。






不要删除锁文件

锁文件存在不代表锁正被占用。删除它可能让两个包管理进程同时修改数据库，造成损坏。不要为了让提示消失就删除 /var/lib/dpkg 下的锁，也不要对更新进程使用强制结束。




等待任务正常结束后再重试原操作。只有系统明确提示“dpkg was interrupted”，并且确认没有其他包管理任务运行时，才执行下面的恢复命令。


【Ubuntu 终端】



可复制命令



$ sudo dpkg --configure -a





像拆句子一样拆开这条命令



提示符
$ 是普通用户提示符，不输入；复制时自动移除。




命令本体
sudo 临时提权；dpkg 处理已解包软件包的配置。




短选项
-a：所有处于待处理状态的软件包。




长选项
--configure：执行配置步骤。




路径 / 参数
无文件路径；只在确认无其他包管理任务且系统提示配置中断时使用。








系统内部发生了什么：继续配置已解包但尚未配置完成的软件包。这是处理中断状态的步骤，不是解除正在使用的锁。


为什么需要管理员权限

修复系统软件包的配置状态会修改包数据库和系统文件，需要管理员权限。




预期输出 · 示意输出

可能显示正在设置软件包；全部已配置时可能没有输出。

$ 不输入。

sudo：校验临时管理授权。




短选项

03 · Permission denied：先问“谁在访问什么”


症状：读取、写入或执行被拒绝。可能原因：文件权限、所属用户、父目录缺少 x、noexec 挂载，或额外的安全规则。只读挂载通常对应另一种写入错误 Read-only file system，要与 Permission denied 区分。权限问题不是一个万能 sudo 能解释的。


【Ubuntu 终端】



可复制命令



$ id
$ pwd
$ ls -ld . ..





像拆句子一样拆开这条命令



提示符
$ 是普通用户提示符，不输入；复制时自动移除。




命令本体
id 查看用户与组；pwd 输出工作目录；ls 查看目录元信息。




短选项
-ld 合并 -l 长列表与 -d 列出目录自身，而不是进入目录列内容。




长选项
无




路径 / 参数
. 是当前目录，.. 是父目录；当前目录的完整路径由 pwd 显示。








系统内部发生了什么：查看当前身份与工作目录，再看当前目录和父目录权限。每层目录的搜索权限都会影响路径访问；先定位失败的那一层。


预期输出 · 示意输出

输出用户与组信息、当前路径，以及两个目录的权限与所有者。






安全解法

自己的脚本缺少执行位，看第 09 项；只读系统配置需要确认目的后使用对应管理工具。项目文件意外属于 root 时，先核对具体文件再调整所有者；不要递归改整个系统，也不要使用全员可写权限掩盖问题。

【Ubuntu 终端】

短选项
-la 合并 -l 长列表与 -a 显示包括点开头项目在内的全部条目。

06 · 中文乱码：编码、区域设置、字体分开查


UTF-8 / locale · 词源、争议与助记






公认词源 / 官方释义争议说法 / 边界助记口诀（不是词源）





UTF：Unicode Transformation Format；UTF-8 是一种 Unicode 编码。locale 指区域设置，如语言、字符分类、日期格式。乱码、方块字、中文输入不出是不同问题：文件编码、字体与输入法分别负责不同层面。编码负责字怎么存，字体负责字怎么画，输入法负责字怎么进来；这是助记。










LANG / LC_ALL · 词源、争议与助记






公认词源 / 官方释义争议说法 / 边界助记口诀（不是词源）





LANG 与 LC_ALL 是区域设置变量名；LANG 指默认语言区域，LC_ALL 可覆盖所有区域分类设置。这里按变量实际语义理解即可，不把 LC 强行解释成未经证实的历史缩写。LANG 给默认值，LC_ALL 暂时统一全部分类；这是助记。










【Ubuntu 终端】



可复制命令



$ locale
$ locale -a





像拆句子一样拆开这条命令



提示符
$ 是普通用户提示符，不输入；复制时自动移除。




命令本体
locale 查看区域设置；第二行列出已安装的区域数据名称。




短选项
-a：列出全部可用 locale 名称。




长选项
无




路径 / 参数
无文件路径。








系统内部发生了什么：查看当前区域变量和系统已生成的可用 locale。若文本文件本身不是 UTF-8，改环境变量不会自动转换文件内容。


预期输出 · 示意输出

第一条显示 LANG 与 LC_*；第二条列出可用 locale，可能包含 en_US.utf8 或 zh_CN.utf8。






若缺少需要的 UTF-8 区域设置，可生成中文 UTF-8，并仅在当前终端试用。英文菜单是否改成中文由更广泛的桌面语言设置决定。


【Ubuntu 终端】

$ sudo locale-gen zh_CN.UTF-8

像拆句子一样拆开这条命令



提示符
$ 是普通用户提示符，不输入；复制时自动移除。




命令本体
sudo 临时提权运行 locale-gen；随后两行 export 只设置当前 shell 的环境变量。




短选项
无




长选项
无




路径 / 参数
zh_CN.UTF-8 是 locale 标识，不是路径；LANG 设默认语言区域，LC_ALL 覆盖当前 shell 的全部区域分类。








系统内部发生了什么：生成区域数据，再把当前 shell 与之后启动的子进程设为中文 UTF-8。这不转码已有文件；LC_ALL 会覆盖该 shell 中其他 LC_* 设置。


为什么需要管理员权限

生成系统 locale 数据写入受保护目录；后两行只改自己的 shell，不需要 sudo。




预期输出 · 示意输出

生成过程可能显示 zh_CN.UTF-8... done；变量赋值通常无输出。






如果字符显示为方块但复制出去正常，检查字体；若字能显示却无法输入中文，回到第 1 章配置输入源。不要同时修改三层，逐层确认变化。






07 · 磁盘满：先定位空间属于谁


df / du · 词源、争议与助记






公认词源 / 官方释义争议说法 / 边界助记口诀（不是词源）





df：disk free；du：disk usage，分别报告文件系统容量和文件目录占用。文件系统统计与目录统计可能因已删除但仍打开的文件、权限、挂载点等原因不同。df 看整仓余量，du 看各货架占用；这是助记。










inode · 词源、争议与助记






公认词源 / 官方释义争议说法 / 边界助记口诀（不是词源）





Unix 文件系统用于记录文件元数据的数据结构名称，常见解释与 index node 有关。历史命名解释并非所有资料一致；学习时把它理解为文件记录名额即可，不当作磁盘字节数。空间像仓库面积，inode 像可登记的物品名额；这是助记。










【Ubuntu 终端】



可复制命令



$ df -h
$ df -i
$ du -h --max-depth=1 "$HOME"





像拆句子一样拆开这条命令



提示符
$ 是普通用户提示符，不输入；复制时自动移除。




命令本体
df 查看文件系统容量或 inode；du 统计目录占用。




短选项
-h：便于阅读的容量单位；df -i：显示 inode 用量。




长选项
du --max-depth=1：只显示到一层子目录的汇总，统计仍遍历其内部。




路径 / 参数
"$HOME" 展开为当前用户家目录，是 du 的统计起点；df 未指定路径，报告各文件系统。








系统内部发生了什么：先看容量，再看 inode 数量，最后只统计你家目录下一层的占用。容量够但 inode 耗尽，也会无法创建新文件。


预期输出 · 示意输出

df 显示各挂载点的容量或 inode 使用率；du 列出家目录下各子目录的用量。

sudo 临时提权；apt 的 clean 子命令清理下载缓存。

无




长选项
无

无文件路径参数；它清理 APT 缓存，不卸载已安装软件。

08 · 网络不通：从网卡到路由，再到名字


症状：网页、apt 或 SSH 无法连接。原因：虚拟网卡未连接、没有地址、缺少默认路由、域名解析失败，或服务与防火墙限制。


getent · 词源、争议与助记






公认词源 / 官方释义争议说法 / 边界助记口诀（不是词源）





getent 用于获取名字服务数据库中的条目，名称对应 get entries 的短写。它按系统配置查询，结果可能来自本地文件，也可能来自网络解析服务；不保证只查某一种来源。向系统通讯录问一个名字；这是助记。










【Ubuntu 终端】



可复制命令

$ ip route
$ getent hosts ubuntu.com





像拆句子一样拆开这条命令



提示符
$ 是普通用户提示符，不输入；复制时自动移除。




命令本体
ip 的 addr 子命令查接口地址，route 子命令查路由；getent 查询系统名字服务。




短选项
无




长选项
无




路径 / 参数
hosts 指主机名数据库，ubuntu.com 是待查域名；本段没有文件路径参数。








系统内部发生了什么：依次查看接口地址、路由表和域名解析结果。第三条通过系统的名字服务配置查询，不要求目标回应 ping。


预期输出 · 示意输出

可能看到 inet 地址、default 路由及域名对应地址；缺失哪一层就先检查哪一层。






【VMware 设置】检查虚拟机“设置 → 网络适配器”的“已连接”和“启动时连接”；入门使用 NAT。先验证宿主机本身能联网，再回 Ubuntu 重试。不要未经判断就手工覆盖 DNS 配置。






09 · 脚本没执行权限：只给自己的文件增加需要的权限


症状：执行自己的 build.sh 得到 Permission denied。原因：文件没有执行位，或者所在挂载点禁止执行；先检查脚本内容与所在位置。下面在独立练习目录创建一个无害脚本。


【Ubuntu 终端】

本章自检


apt 锁文件可以直接删除吗？

不可以。锁由运行中的进程持有，文件存在本身不代表占锁；应等待正常任务完成并排查真实原因。




乱码与方块字一定是同一件事吗？

不是。乱码常涉及编码解释；方块字可能缺少字体；无法输入还可能是输入法问题。




磁盘还有容量，却无法创建新文件，还查什么？

检查 inode 是否耗尽，也检查挂载是否只读、用户配额及目录权限。




Ctrl+S 后屏幕不动了，首先试什么？

试 Ctrl+Q 恢复输出；不要立刻重启虚拟机。

术语对照与学习路线复盘

从 Windows 经验接到 Linux 语言







英文术语中文与 Windows 对照你要保留的区别





distribution发行版：包含内核、软件仓库与桌面等的一整套系统。Ubuntu 是发行版，Linux 严格说指内核，不能把两者完全等同。



kernel内核：操作系统管理硬件与资源的核心。桌面外观改变不等于换了内核。



desktop environment桌面环境：类似桌面、任务栏、窗口管理这一套体验。Ubuntu 24.04 主线使用 GNOME 46；不是所有 Linux 都长这样。



terminal终端：承载命令输入输出的窗口。窗口与解释命令的 shell 是两层。



shell命令解释器：把输入解析为要执行的动作。Bash、其他 shell 的配置与语法可能不同。



filesystem文件系统：组织文件与目录的方式。Linux 统一从 / 访问目录；磁盘接入不必新增盘符。



mount / mount point挂载 / 挂载点：让文件系统内容接入一个目录。目录名是入口，不等同于某块硬盘本身。



home directory家目录：类似你的 Windows 用户文件夹。/home/用户名、~ 与 /root 不可混淆。



working directory当前工作目录：此刻命令站立的位置。相对路径从这里出发；pwd 随时确认。



permission / ownership权限 / 所有权：谁能做什么、文件属于谁。读、写、执行对文件与目录的含义不同。



root / sudo超级用户 / 临时按授权执行管理命令。sudo 不是修复所有问题的前缀；root 家目录是 /root。



repository / package软件仓库 / 软件包：受管理的软件来源与分发单位。系统仓库、PPA、下载的 .deb 与 snap 有不同的来源和更新方式。



process / signal进程 / 信号：运行中的程序实例与发给它的通知。结束窗口、结束进程和关闭系统不是同一个动作。



environment variable环境变量：程序继承的运行环境信息。当前终端变量与持久配置不是一回事。



pipe / redirection管道 / 重定向：接力文本与改变输入输出目的地。管道默认连接标准输出；> 会覆盖目标。



header / linker头文件 / 链接器：接口声明与组合目标代码的工具。找不到头文件是编译阶段问题；找不到函数实现可能出现在链接阶段。



toolchain / cross compilation工具链 / 交叉编译：一组开发工具与为另一平台构建。开发电脑与目标板的处理器、库和运行环境需要匹配。



snapshot / backup快照 / 备份：恢复某个虚拟机状态与独立保存资料。快照依赖原有虚拟机文件，不能替代独立备份。












把术语分组，比机械背诵轻松


第一组是“我在哪里”：桌面、终端、当前目录、绝对路径。第二组是“我能做什么”：用户、组、权限、sudo。第三组是“工具从哪里来”：仓库、软件包、PATH。最后一组是“程序怎么活着”：进程、信号、网络和日志。
